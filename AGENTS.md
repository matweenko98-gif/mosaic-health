# Правила для ИИ-ассистентов (Antigravity, Cursor, Copilot, Claude и др.)

Этот файл читают ИИ-инструменты разработки. Соблюдай эти правила в любом инструменте.

## 1. Карта проекта — читать ПЕРВОЙ
Перед любыми изменениями открой **[`ARCHITECTURE.md`](ARCHITECTURE.md)** — это единственный источник правды
по структуре: модули, все эндпоинты, модель данных, экраны, что подключено к серверу, правила деплоя.
Не ищи по всем файлам вслепую — сначала карта.

## 2. ⚠️ ГЛАВНОЕ: обновляй ARCHITECTURE.md
**После КАЖДОГО значимого изменения обнови `ARCHITECTURE.md`** — иначе карта устаревает и все ИИ начинают ошибаться.

Обновляй, если изменил:
- новый или изменённый **эндпоинт** → таблица «Полный список эндпоинтов»
- поле/таблицу в **базе** (`schema.prisma`) → раздел «Модель данных»
- новый **экран** или `currentScreen`-id → таблица экранов
- новый **модуль** бэкенда → таблица модулей
- что-то стало браться **с сервера** вместо локального → раздел «Что подключено к серверу»
- правила **деплоя/окружения** → соответствующий раздел

**Всегда** добавляй строку в раздел **«Журнал изменений»** внизу файла: `| ДАТА | что сделано |`.

## 3. Стиль и рамки (из `.ai-rules`)
- Русский язык: комментарии, тексты интерфейса, сообщения об ошибках.
- UI: соблюдай консистентность с существующими кнопками/карточками, не зажимай текст, оставляй «воздух».
- Работай только с активной структурой. Мёртвые артефакты (`Мозаика Здоровья 2.html`, `backup_headers/`,
  следы shadcn) — игнорируй, не восстанавливай.

## 4. Совместная разработка
- Двое разработчиков + разные ИИ. **Перед работой — `git pull`**, после — `git push`.
- Vercel деплоится сам при push. Render — через Deploy Hook (GitHub Action) или Manual Deploy.
- Бесплатный Supabase засыпает после ~недели простоя → сборка Render падает `tenant/user not found` →
  лечится кнопкой **Restore** в Supabase.
